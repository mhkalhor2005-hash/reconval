# ریکنوال — پلتفرم مدیریت فروش و ویزیت پزشکان (MVP)

این پروژه نسخه اول (MVP) پلتفرم اختصاصی تیم فروش ریکنوال است: یک پنل مدیریتی تحت وب برای مدیر فروش، و یک اپلیکیشن وب موبایل (PWA) برای ویزیتورها. مطابق سندی که پیش از این آماده شد، این نسخه روی سه اولویت اول تمرکز دارد: ثبت ویزیت و پروفایل پزشک، مدیریت نمونه دارویی و هدایا، و داشبورد مدیریتی/KPI.

## اجرای سریع (محلی)

پیش‌نیاز: **Node.js نسخه 22.5 یا بالاتر** (چون از ماژول توکار `node:sqlite` استفاده شده و نیازی به نصب دیتابیس جداگانه نیست).

```bash
npm install
npm run db:seed   # فقط بار اول: دیتابیس نمونه با کاربران/پزشکان/ویزیت‌های آزمایشی می‌سازد
npm run dev
```

سپس آدرس `http://localhost:3000` را باز کنید.

> نکته: یک دیتابیس نمونه از قبل در `data/app.db` قرار داده شده، پس حتی بدون اجرای `db:seed` هم پروژه با داده آزمایشی بالا می‌آید. برای شروع از صفر: `npm run db:reset`.

### حساب‌های نمایشی

| نقش | نام کاربری | رمز عبور |
|---|---|---|
| مدیر فروش | `manager` | `manager123` |
| ویزیتور | `rep1`, `rep2`, `rep3` | `rep123` |

## دستورات

- `npm run dev` — اجرای محیط توسعه
- `npm run build` — بیلد نسخه تولید (production)
- `npm run start` — اجرای نسخه بیلدشده
- `npm run db:seed` — افزودن داده نمونه (idempotent — دوباره اجرا کردنش مشکلی ایجاد نمی‌کند)
- `npm run db:reset` — پاک کردن کامل دیتابیس و ساخت دوباره از صفر با داده نمونه

## این نسخه چه چیزی دارد

- **مدیریت کاربران و نقش‌ها**: ورود امن (JWT در کوکی httpOnly)، نقش «مدیر فروش» و «ویزیتور»
- **پروفایل پزشک و مرکز درمانی**: ثبت، جستجو، ویرایش، موقعیت روی نقشه، تاریخچه کامل تعاملات
- **ثبت ویزیت با چک‌این GPS**: شروع/پایان ویزیت با موقعیت مکانی و زمان، نتیجه ویزیت، یادداشت
- **حالت آفلاین**: اگر ویزیتور اینترنت نداشته باشد، ویزیت به‌صورت محلی (در مرورگر) ذخیره و به محض اتصال مجدد به‌صورت خودکار با سرور همگام‌سازی می‌شود (به‌همراه شناسه یکتا برای جلوگیری از ثبت تکراری)
- **مدیریت نمونه دارویی و هدایا**: کاتالوگ محصول، تخصیص موجودی به هر ویزیتور، ثبت تحویل نمونه در حین ویزیت و کسر خودکار از موجودی
- **داشبورد مدیریتی و KPI**: عملکرد هر ویزیتور در برابر هدف ماهانه، نقشه پراکندگی بازدیدها (بدون نیاز به کلید API نقشه)، گزارش مصرف نمونه دارویی
- **PWA**: قابل نصب روی موبایل ویزیتور از طریق مرورگر، بدون نیاز به مارکت

## پشته فناوری

- **Next.js 16** (App Router, TypeScript, Turbopack)
- **node:sqlite** — دیتابیس توکار Node.js (بدون نیاز به نصب/دانلود جداگانه؛ برای مقیاس بزرگ‌تر به‌راحتی قابل مهاجرت به PostgreSQL است)
- **Tailwind CSS 4**
- **Leaflet + OpenStreetMap** برای نقشه (بدون کلید API؛ برای استقرار نهایی در ایران پیشنهاد می‌شود Tile Layer به نشان یا بلد تغییر کند — محل تغییر: `src/components/VisitsMap.tsx`)
- **@fontsource-variable/vazirmatn** — فونت فارسی به‌صورت self-host (بدون وابستگی به Google Fonts)
- **jose + bcryptjs** برای احراز هویت

## ساختار پروژه (خلاصه)

```
src/
  app/
    (site)            صفحه فرود عمومی → src/app/page.tsx
    login/             صفحه ورود
    dashboard/         پنل مدیر فروش (نمای کلی، پزشکان، ویزیتورها، محصولات، ویزیت‌ها)
    app/               اپ ویزیتور (PWA) — خانه، پزشکان، ویزیت جاری، تاریخچه، موجودی
    api/               Route Handlerهای بک‌اند (REST)
  components/          کامپوننت‌های مشترک (فرم‌ها، نقشه، صف آفلاین و ...)
  lib/
    db.ts              اتصال به SQLite
    schema.ts           تعریف جدول‌ها
    auth.ts             سشن و رمزنگاری
    offlineQueue.ts      منطق صف آفلاین سمت مرورگر
    repo/                توابع دسترسی به داده (پزشکان، ویزیت‌ها، محصولات، موجودی، داشبورد)
scripts/seed.ts        اسکریپت داده نمونه
public/manifest.json   مانیفست PWA
public/sw.js           Service Worker (کش پوسته برنامه برای حالت آفلاین)
```

## نکات مهم قبل از استقرار روی سرور واقعی (Production)

1. **`SESSION_SECRET`**: همین حالا از یک مقدار پیش‌فرض ناامن استفاده می‌شود. قبل از استقرار واقعی، یک مقدار تصادفی طولانی در متغیر محیطی `SESSION_SECRET` تنظیم کنید (مثلاً با `openssl rand -hex 32`).
2. **HTTPS الزامی است**: چون از GPS مرورگر (Geolocation API) و Service Worker استفاده شده، این‌ها فقط روی HTTPS (یا localhost) کار می‌کنند.
3. **میزبانی داخل ایران**: طبق پیشنهاد اولیه، برای بهترین کارکرد (به‌خصوص برای دسترسی پایدار تیم ویزیتور) میزبانی روی یک سرویس ابری داخلی مثل آروان کلاود یا لیارا توصیه می‌شود. این پروژه از قبل هیچ وابستگی سخت به سرویس‌های گوگل ندارد (نه فونت، نه نقشه).
4. **دیتابیس**: `node:sqlite` برای تیم زیر ۲۰-۳۰ نفر کاملاً کافی است. اگر تیم به‌طور محسوسی بزرگ‌تر شد، مهاجرت به PostgreSQL (مثلاً با Prisma یا Drizzle) گام بعدی طبیعی است؛ لایه `src/lib/repo/*` طوری طراحی شده که این مهاجرت را ساده می‌کند.
5. این نسخه یک **MVP** است، نه محصول نهایی. فازهای بعدی (مسیریابی هوشمند، پیش‌فاکتور/سفارش، گزارش پیشرفته، هوش مصنوعی پیشنهاد بازدید، اتصال به انبار/حسابداری) طبق سند پیشنهادی، در مراحل بعدی قابل افزودن هستند.

## نحوه کار حالت آفلاین (فنی)

وقتی ویزیتور اینترنت ندارد:
1. با کلیک روی «شروع ویزیت»، به‌جای فراخوانی سرور، یک رکورد محلی در `localStorage` مرورگر ساخته می‌شود (همراه با شناسه یکتا).
2. در پایان ویزیت، اطلاعات کامل (نتیجه، یادداشت، نمونه‌های تحویلی) به یک صف محلی اضافه می‌شود.
3. به محض اتصال مجدد به اینترنت (رویداد `online` مرورگر یا بررسی دوره‌ای هر ۱۵ ثانیه)، صف به‌صورت خودکار به `POST /api/visits/sync` ارسال می‌شود.
4. سرور با استفاده از شناسه یکتای هر ویزیت، از ثبت تکراری جلوگیری می‌کند (idempotent).

Service Worker (`public/sw.js`) هم پوسته اصلی برنامه (صفحات و فایل‌های استاتیک) را کش می‌کند تا اپلیکیشن حتی بدون اینترنت باز شود؛ اما تماس‌های `/api/*` عمداً کش نمی‌شوند تا داده همیشه واقعی باشد یا صراحتاً در صف آفلاین قرار بگیرد.
